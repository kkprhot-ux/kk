## 1. 项目概述

### 1.1 一句话定位

一个 **24 小时待命的个人语音助理**：手机当"耳朵"，电脑当"大脑"，实时监听并分析您周围对话，长期记忆，定期出周报，**数据全部本地存储**。

### 1.2 核心价值

- 🧠 **解放大脑**：不用手动记录，AI 帮您记住每段对话
- 📊 **自我认知**：看见自己的生活 / 工作 / 情绪曲线
- 🤖 **主动助理**：基于长期记忆给个性化建议
- 🔒 **隐私第一**：音频听完即丢，所有数据本地化

### 1.3 类似产品参考

科大讯飞、飞书类似产品，售价 900 元 / 年。本项目为**零成本复刻**，且**数据完全本地化不上云**。

## 2. 用户原始诉求

用户最初提出的需求核心要点：

1. 手机麦克风实时监听，**说话时变红、不说话变蓝**（VAD 智能开关）
2. 实时分析对话内容，**自动总结**
3. 生活 / 工作 / 情绪**三维度**分析
4. **长期记忆**不丢失
5. **每周对话总结**给建议
6. **自动提醒**（根据对话内容生成）+ 手动普通提醒
7. **带长期记忆的 AI 聊天**（不会"忘了"之前的事）
8. **人物图谱**（音频里提到的人自动收录）
9. **本地部署**，电脑端为主，手机端轻量
10. 持续后台监听，**手机不发烫、省电**

### 4.2 数据流（7 步走）

| # | 步骤 | 在哪里 | 发生了什么 |
|---|---|---|---|
| 1 | 🎤 监听 | 手机 | 麦克风一直待机，检测人声 |
| 2 | 🔊 推流 | 手机→电脑 | 有人说话 → 音频流推到电脑 |
| 3 | 📝 转写 | 电脑 | 音频流 → 实时转文字（讯飞 ASR） |
| 4 | 🤖 分析 | 电脑→云 | 文字片段 → DeepSeek 分析 |
| 5 | 📊 存库 | 电脑 | 分析结果 + 文字 → 本地数据库 |
| 6 | 🔔 提醒 | 电脑 | 自动生成提醒（如有） |
| 7 | 📱 显示 | 手机+电脑 | UI 实时显示给用户看 |

### 4.3 四大核心原则

| 原则 | 实现方式 |
|---|---|
| 🔒 **音频不上传** | 手机推流到电脑，电脑转完文字**立刻丢弃音频** |
| 🔒 **文字不完整上传** | 只上传需要分析的"片段"，完整文字留本地 |
| 💾 **本地存储** | 所有对话、分析、提醒、人物都在本地 |
| 🔄 **自动备份** | 每天备份到 D 盘（保留 30 天） |

## 5. 核心功能流程

### 5.1 7 个关键环节

#### ① 监听（VAD - 语音活动检测）

- 麦克风持续监听
- 检测到人声 → **开始推流**
- 静音 5 秒 → **停止推流，提交一段对话**

#### ② 音频传输

- 局域网 WebSocket 推流
- Opus 编码（低延迟、压缩好）
- 端到端延迟约 **200-300ms**

#### ③ 转写（ASR）

- 使用 **讯飞流式 API**（中文准，0.003 元/秒）
- 实时流式转写，文字片段持续累积

#### ④ 对话段切分

- 静音 **5 秒** 自动切分一段对话
- 不做大模型判断（太慢、太贵）

#### ⑤ AI 分析（每段对话都做）

一次调用返回多个结果：

\\\json
{
  "topic": "工作 / 生活 / 社交",
  "sentiment": {
    "user": "开心 / 平淡 / 焦虑 / 沮丧",
    "other": "..."
  },
  "summary": "一句话总结这段对话",
  "reminders": [
    "周五前交报告",
    "记得给妈打电话"
  ],
  "people_mentioned": ["张三", "李雷"],
  "importance": 3
}
\\\

#### ⑥ 长期记忆

**存储结构**：
- 📅 **每日摘要**（每天 23:50 自动生成）
- 📊 **每周摘要**（每周日晚生成）
- 🔍 **检索索引**（按主题 + 关键词）

**使用时**（AI 聊天）：
- 用户提问 → 检索最相关的 **5-10 段**历史摘要
- 把这些摘要 + 当前问题 → 喂给 DeepSeek
- DeepSeek 给出有上下文的回答

#### ⑦ AI 聊天的上下文注入

- 系统 prompt：固定部分（用户身份、当前时间、规则）
- 动态注入：
  - 相关历史摘要（5-10 段）
  - 相关人物档案
  - 最近的 1-2 段对话上下文
- 总 token 控制在 **3000-5000**

## 6. 数据存储

### 6.1 数据库选型

**SQLite**（推荐）
- 单文件、零配置、性能足够
- 好备份（备份即复制一个文件）
- 一年数据量预计 10-100MB，绰绰有余

### 6.2 文件位置

\\\
D:\PersonalAssistant\
├── data\
│   └── assistant.db              ← 主数据库
├── logs\
│   └── assistant-YYYY-MM-DD.log  ← 运行日志
├── config\
│   └── settings.yaml             ← 配置（API Key 等）
└── backup\                       ← （备份统一放 D 盘根目录）
\\\

### 6.3 4 张表结构

#### 表 1：\conversations\（对话记录）

| 字段 | 类型 | 说明 |

| start_time | DATETIME | 对话开始时间 |
| duration_sec | INTEGER | 持续秒数 |
| content | TEXT | 完整文字 |
| analysis_json | TEXT | AI 分析结果（JSON） |
| topic | TEXT | 主题（生活/工作/社交） |
| importance | INTEGER | 重要程度 1-5 |
| created_at | DATETIME | 入库时间 |

#### 表 2：\eminders\（提醒）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| content | TEXT | 提醒内容 |
| due_time | DATETIME | 截止时间 |
| status | TEXT | pending/done/expired |
| source | TEXT | auto/manual |
| created_at | DATETIME | 创建时间 |
| completed_at | DATETIME | 完成时间 |

#### 表 3：\people\（人物档案）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| name | TEXT | 姓名 |
| identity | TEXT | 一句话身份 |
| relationship | TEXT | 与用户的关系 |
| first_seen | DATETIME | 首次出现 |
| last_seen | DATETIME | 最后出现 |
| mention_count | INTEGER | 被提及次数 |

#### 表 4：\memories\（长期记忆）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| period | TEXT | daily/weekly |
| start_date | DATE | 起始日期 |
| end_date | DATE | 结束日期 |
| summary | TEXT | 摘要内容 |
| topics | TEXT | 主题列表（逗号分隔） |
| key_events | TEXT | 关键事件 |

#### 索引（加速查询）

- \conversations.start_time\（按时间查）
- \conversations.topic\（按主题查）
- \people.name\（按姓名查）
- \memories.period + start_date\（按周期查）

### 6.4 备份策略

| 项目 | 决策 |
|---|---|
| **备份时间** | 每天凌晨 02:00 |
| **备份位置** | \D:\PersonalAssistantBackup\（优先），没有 D 盘则降级到 \C:\Users\<用户名>\Documents\PersonalAssistantBackup\ |
| **文件名** | \ssistant_YYYY-MM-DD.db.gz\（gzip 压缩） |
| **保留策略** | 最近 **30 天**，自动清理 |
| **备份过程** | 复制数据库 → gzip 压缩 → 保存 |

### 6.5 数据生命周期

| 数据类型 | 保留策略 |
|---|---|
| 对话记录 + 分析 | **永久保留** |
| 人物档案 | **永久保留** |
| 长期记忆摘要 | **永久保留** |
| 提醒（已完成/过期） | 完成后保留 90 天后归档 |
| 提醒（待办） | 永久保留直到完成 |
| 运行日志 | 保留最近 30 天 |

## 8. 技术选型

### 8.1 手机端

| 项目 | 选型 |
|---|---|
| 平台 | Android（Kotlin/Java） |
| 最低 SDK | 26（Android 8.0，覆盖小米 8 青春版） |
| 音频采集 | AudioRecord API |
| VAD 检测 | silero-vad-android（开源本地 VAD） |
| 音频编码 | Opus |
| 推流协议 | WebSocket（局域网） |
| 后台保活 | 前台服务 + WorkManager + 通知占位 |
| UI | Jetpack Compose（现代化） |
| 数据存储 | Room（SQLite ORM） |
| 网络 | OkHttp + Retrofit |

### 8.2 电脑端

| 项目 | 选型 |
|---|---|
| 桌面框架 | **Tauri**（轻量，Rust 内核 + Web UI） |
| 后端服务 | Python（FastAPI）或 Node.js |
| 音频接收 | WebSocket 服务 |
| ASR | 讯飞流式 API |
| LLM | DeepSeek API（可换 Qwen） |
| 数据库 | SQLite + SQLAlchemy |
| 定时任务 | APScheduler（每日摘要、每周周报、备份） |
| UI | Vue 3 + Element Plus（Tauri 内嵌 WebView） |
| 系统托盘 | Tauri 内置支持 |

**为什么选 Tauri 而不是 Electron**：
- 入门级电脑友好（Tauri 安装包 ~10MB，Electron ~150MB）
- 内存占用低（Tauri ~50MB，Electron ~150MB）
- 启动快（您电脑配置入门级，这个很重要）

### 8.3 通信协议

- 局域网：**WebSocket**（音频推流 + 控制信令）
- 云端：**HTTPS**（AI API 调用）

## 10. 已知风险与缓解

### 10.1 MIUI 14 后台保活风险

- **风险**：MIUI 14 后台管控业界最严，失败概率 10-30%
- **缓解**：
  - 全套保活（前台服务 + 通知占位 + 自启动 + 锁任务 + 电诈防护白名单）
  - App 内置"心跳检测"，被杀会主动尝试重启
  - 写一份 5 分钟图文设置教程
  - 用户每天手动检查一次（30 秒）

### 10.2 入门级电脑性能风险

- **风险**：跑 AI 任务可能慢
- **缓解**：所有重活（AI 分析、摘要、聊天）全跑云端，电脑只做轻处理（转写结果入库、UI 渲染）

### 10.3 ASR 成本风险

- **风险**：24h 持续监听，ASR 费用不低
- **缓解**：
  - VAD 严格（不说话不录音、不转写）
  - 估算：讯飞 0.003 元/秒，一天平均 2 小时有效语音 ≈ 0.003 × 7200 = **21.6 元/天** = **648 元/月**
  - ⚠️ **这个成本超预算！需要优化**：
    - 选更便宜的 ASR（如阿里云、Whisper 本地）
    - 或者限制每天监听时长
    - **第一版先跑通，成本优化放第二版**

### 10.4 24h 持续监听的隐私边界

- **风险**：可能录到不想被录的对话
- **缓解**：
  - 提供"暂停监听"按钮（快捷键 + 通知栏 + 主界面）
  - 提供"敏感时段"配置（如晚上 11 点到早 7 点自动暂停）
  - 在 UI 上明确显示监听状态（红/蓝）
